Design decisions

DecisionWhy
The hedge rule is a pure functionpolicy.decide() takes the book, market snapshot and policy and returns decisions, with no network or database access. The backtest calls the same function, and an assert stops it from seeing a rate dated after the decision day.
No LLM in the decision pathWe tried it: the same invoice worded two ways got two different ratios, and it can't be backtested. The rule hedges more when cover is cheap relative to VaR, always inside the board's range for that tenor.
Outbox with content-derived keysEach action's key is a hash of what it does (invoice, amount, due date). Proposing it again returns the existing row. A crash between the payment call and the DB write is reconciled by looking up the receipt, so the payment happens once.
Checkpoint per step, run id from inputThe run id is a hash of the invoices and flags, so a restart finds its own checkpoints. Nothing already fetched is fetched again and nothing already proposed is proposed again.
Fail closedMissing amount, supplier or due date, a lookalike name, a bank-detail change, or FX data outside sanity bounds all end in a hold with the reason written out. No defaults.
SQLite in WAL modeOne file, no server to run, crash-safe writes. The limit is a single writer; for 100x volume or a second client we'd move to Postgres with a schema per client and keep one shared market-data cache.
